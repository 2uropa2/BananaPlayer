01 / Assessment

출시 실험을 할 근거는 있다.

플레이어의 실제 구현과 제품 설계에 도메인 경험이 반영되어 있다. 작은 수익을 첫 목표로 삼아 검증할 가치는 충분하며, 장기적으로는 여러 도구가 같은 사용자를 함께 돕는 방향이 더 설득력 있다.

용돈벌이는 첫 검증 단계다.
장기 목표는 특정 영상 작업에서 Banana가 반복해서 선택되는 것이다.

현재 판단은 “출시해 볼 만한 제품이 있다”이다. 지속적인 유료 수요, 두 제품 사이의 이용 연결, macOS 수요와 생태계의 확장성은 실제 사용자 데이터로 확인해야 한다.

구현에서 확인

전문가의 판단이 제품에 들어 있다

싱크 보정, 세 스레드 재생 파이프라인, 앞뒤 프레임 이동, 픽셀 비율과 회전, 탐색 직후 복구, 클릭·단축키·오버레이 규칙에 의도가 있다. 이런 선택이 일관된 사용감의 재료가 된다.

사업성 판단

사용자를 바꿔 오게 할 작업을 좁힌다

먼저 장면을 자주 찾고 반복 확인하는 사람에게 편의를 증명한다. 그다음 변환과 결과 확인을 연결해, 하나의 제품을 쓰던 사람이 다른 Banana 도구도 자연스럽게 선택하도록 한다.

Player는 코드 검토·Release 재빌드·테스트 실행을 근거로 평가했다. Trans는 브랜드 문서, 아키텍처, 최신 작업일지와 사이트를 참고했으며 이번 문서 작업에서 전체 코드 감사나 테스트 재실행을 수행하지 않았다. 시장 점유율과 성공 확률을 수치로 단정하지 않는다.

02 / Owner decisions

이번 대화에서 확정된 방향

방향사용자의 의도운영에 반영할 의미
바이브 코딩 중심코드를 직접 작성하지 않고 Codex·Claude의 도움으로 개발과 유지보수를 계속한다.제품의 판단과 우선순위는 사용자가 갖고, 구현·테스트·문서·배포 절차를 하네스로 반복한다.
큰 설계 유지현재 머릿속에 있는 설계와 제품의 방향을 계속 유지한다.세션이 바뀌어도 의도가 이어지도록 중요한 설계 결정과 승인 기준을 기록한다.
Mac 버전 확장Player를 macOS까지 확장할 예정이다.Windows 안정화와 함께 플랫폼 경계를 준비하고, 실제 Mac 검증을 별도로 진행한다.
같은 브랜딩Player와 QualiaTranscoder를 같은 브랜드로 묶는다.현재 사용자 브랜드인 Banana Player·Banana Trans를 같은 제품군으로 설명한다.
동영상 생태계마이너 또는 중간 규모의 동영상 도구 시장에서 넓은 존재감을 확보한다.첫 소액 수익을 상한으로 삼지 않고, 인접한 작업과 고객군으로 단계적으로 확장한다.

“다 먹는다”를 실행 기준으로 바꾸면: 선택한 사용자군이 영상 검토·변환·결과 비교·출력을 반복할 때 Banana를 기본 도구로 쓰는 상태다. 제품 개수보다 반복 사용과 작업 연결을 먼저 쌓는다.

통합 브랜딩은 확정된 사용자 방향이다. 이 문서의 제품 역할, 확장 순서, 가격 실험과 추가 도구 후보는 분석에 따른 제안이며, 이미 구현되었거나 모두 개발하기로 확정된 기능을 뜻하지 않는다.

03 / Product family

Player가 입구를 만들고, Trans가 다음 작업을 맡는다.

같은 브랜드는 두 앱이 같은 사용자와 같은 약속을 공유할 때 힘을 얻는다. “영상의 상태를 이해하고, 의도한 결과를 쉽게 얻는다”는 약속을 중심에 둔다. Player에서 확인한 소스를 Trans로 변환하고, 결과를 다시 Player에서 확인하는 흐름이 첫 연결 후보다.

04 · USER업로드·공유·납품

사용자가 목적한 다음 작업을 끝낸다.

위 흐름은 제품 연동 제안이다. 현재 자동 전달·동기화 비교·공통 작업 기록이 구현되어 있다는 뜻은 아니다.

반복 수요 확인 후의 확장 후보

비교·검수·일괄 작업

원본/결과 같은 시점 비교, 변환 결과 리포트, 여러 파일의 이상 구간 확인, 일괄 처리 같은 인접 작업을 후보로 둔다. 초기에는 기존 두 제품의 기능으로 해결하고, 별도 제품은 독립적인 고객과 결제 이유가 확인될 때 검토한다.

B2B QC·CLI는 장기 후보다. 도구 구현에 더해 정확성 보증, 계약, 도입 지원과 운영 책임이 필요하므로 지원 부담이 낮다고 가정하지 않는다.

브랜드는 함께, 제품 역할은 명확하게.

Banana→Banana PlayerBanana Trans
  • 하나의 브랜드 사이트에 제품별 소개와 다운로드를 둔다. Player와 Trans의 용도·지원 플랫폼·가격은 각각 분명히 표시한다.
  • 색·아이콘·단축키 철학·오류 설명·도움말의 톤을 맞춘다. Player의 기존 바나나 노란색을 제품군 공통 강조색으로 사용할 수 있다.
  • 연동은 파일과 시간 정보 전달처럼 작은 기능부터 검증한다. 브랜드 통합만으로 엔진·저장소를 합칠 필요는 없다.
  • Player의 자체 재생 엔진과 Trans의 VidCore는 현재 다른 구조다. 공통화할 항목은 실제 중복, 테스트 안정성, 배포 라이선스를 확인한 뒤 정한다.

브랜드 소개 초안 · 영상을 확인하고, 원하는 크기와 품질로 준비하세요.

16년의 동영상 개발 경험으로 설계한 Banana 도구들. Player로 확인하고, Trans로 변환합니다.
04 / Users & positioning

작은 리그도 구체적인 작업에서 시작한다.

첫 타깃은 로컬 영상을 자주 열고, 장면을 반복 확인하며, 필요에 따라 변환까지 하는 사람이다. 넓은 사용자에게 모든 기능을 설명하기보다 같은 작업의 불편을 먼저 줄인다.

사용자 후보반복되는 작업먼저 보여줄 가치
개인 편집자·크리에이터원본 확인 → 필요한 장면 찾기 → 업로드용 변환탐색과 프레임 이동의 사용감, 결과를 쉽게 재확인하는 흐름
영상 QA·자막 검수자특정 시점 반복 확인, 싱크·자막·재생 상태 점검반복 탐색·북마크·재생 정보, 검토 결과를 정리할 가능성
영상 파일을 자주 공유하는 사람재생 가능 여부 확인, 파일 용량과 호환성 조정Player와 Trans를 함께 사용했을 때의 작업 편의

경쟁의 기준은 높다. VLC는 무료·광고 없음·사용자 추적 없음으로 안내한다. mpv에는 프레임 이동, A-B 반복, 캡처와 싱크 조정이 이미 있다. 곰플레이어+는 확인 시점에 평생 이용권 행사 가격 11,000원을 표시했다. 따라서 깔끔한 UI나 기능 목록만으로 구매를 기대하기 어렵다.

증명할 질문: “이 사용자는 어떤 작업에서 기존 도구 대신 Banana를 열며, 두 도구를 함께 썼을 때 무엇이 편해지는가?” 답은 실제 사용과 결제 이유로 확인한다.

현재 구간 저장은 키프레임 기준으로 시작할 수 있다. 배속 재생은 음정이 변하고, ASS 자막은 스타일을 제거해 표시한다. 프레임 단위 정확 컷 편집, 강의 배속 청취, 복잡한 자막 표현, 색 기준 검수를 주력 가치로 홍보하려면 각각 추가 구현과 검증이 필요하다.

첫 서비스 페이지에는 실제 탐색 → 앞뒤 프레임 이동 → 캡처 → 구간 저장을 보여주는 짧은 데모를 둔다. 16년의 경험은 이 사용 경험을 뒷받침하는 개발자 소개에 담고, AI 개발 과정은 개발기에서 설명할 수 있다.

Trans의 “용량은 절반, 화질은 그대로” 같은 문구는 측정 조건과 적용 범위를 함께 설명해야 한다. 최신 작업일지에서도 콘텐츠와 HW 인코더에 따른 편차가 관찰된다. 특정 샘플 결과를 모든 영상의 결과로 일반화하지 않는다.

01 · 캡처는 배포 구성을 포함한 기능

소스에 PNG 저장 코드가 있어도 동봉 라이브러리에 인코더가 없으면 작동하지 않는다. 인코더 확인과 실제 파일 생성 검증을 출시 하네스에 넣는다.

02 · 공유 데이터는 소유권까지 검증

배너를 읽는 동안 같은 데이터가 갱신되는 문제를 재현했다. 데이터를 안전하게 읽는 방식과 갱신 검증을 함께 보완한다. 실제 UI 크래시가 관찰되었다는 뜻은 아니다.

  • 일반 CI에는 현재 별도 통합 테스트가 연결되어 있지 않다. 하네스 자체를 고치고 중요한 회귀 항목을 릴리스 기준에 포함한다.
  • 기존 설치 패키지는 최근 수정 전의 파일이다. 최신 소스를 재패키징하고 깨끗한 환경에서 설치·실행·업데이트·제거를 확인한다.
  • 현재 확인한 설치 파일과 실행 파일은 서명되지 않았다. 배포 경로와 서명 전략을 정하고, 초기 사용자에게 설치 상태를 명확히 안내한다. 서명만으로 새 파일의 SmartScreen 경고가 즉시 사라지는 것은 아니다. Microsoft 공식 안내
  • Player 동봉 FFmpeg는 LGPL 구성으로 확인했다. 배포 문구만으로 완료했다고 가정하지 않고 해당 빌드 소스·빌드 정보 등 공식 배포 가이드를 반영한다. Trans의 GPL 포함 여부와 배포 방식은 별도로 정리한다.

현재 목표는 작은 베타를 안전하게 배포하는 것이다. Trans의 배포·과금 준비 상태는 Player의 테스트 결과로 대신 판단할 수 없다.

06 / Monetization

첫 결제와 지속 매출을 따로 확인한다.

현재 Player Pro 라이선스의 핵심 효과는 프로모 배너를 숨기는 것이다. 대부분의 실제 기능은 무료와 같다. 처음에는 9,900원 정도의 후원판으로 솔직하게 설명하고, 실제 기능에 대한 결제 이유는 반복 사용자의 요청에서 찾는 방법을 제안한다.

Player의 첫 수익 실험

무료 기본 재생 + 선택적인 일회성 후원. 지인이 아닌 사용자가 왜 결제했는지 기록한다. 후원은 첫 수익을 보여 주지만 유료 기능 수요와 지속 매출을 자동으로 증명하지 않는다.

제품군의 다음 수익 실험

Trans의 반복 변환 작업, 결과 비교나 작업 정리에서 지불 의사를 확인한다. 사용자 겹침이 확인되면 번들·공동 혜택을 실험한다. 계정·구독·통합 결제는 필요가 확인된 다음에 구축한다.

광고는 초기 우선순위를 낮춘다. 자체 배너를 띄우는 기능과 광고주를 확보해 수익을 얻는 일은 다르다. AdFit 공식 안내도 현재 사전 승인 또는 초대가 필요하다고 설명한다. 수익화 문서의 광고 매출은 검증된 수입으로 볼 수 없다.

07 / macOS expansion

Mac은 제품군의 범위를 넓히는 다음 투자다.

macOS 확장은 사용자의 확정된 방향이다. Player와 Trans를 같은 작업 도구군으로 만드는 데 도움이 될 수 있다. 다만 Windows 버전이 빌드된다는 사실만으로 Mac의 사용성과 배포 준비를 추정할 수는 없다.

IINA는 무료·오픈소스 macOS 플레이어이며 트랙패드, 미디어 제어와 PiP 등 플랫폼 사용감을 강조한다. HandBrake는 Windows·Mac·Linux에서 제공되는 무료 트랜스코더다. Mac에서도 반복 검토와 변환 연결의 실익을 보여 주어야 한다.

08 / Vibe coding operating model

큰 그림을 가진 사람이 제품을 지휘한다.

바이브 코딩은 앞으로도 이 프로젝트의 중심 개발 방식이다. 사용자는 제품의 의도·설계·우선순위를 유지하고, AI는 구현·회귀 검증·문서·배포 작업을 수행한다. 코드 타이핑 여부보다 중요한 것은 작은 변경이 실제 동작과 배포본까지 일관되게 검증되는가이다.

제품 의도와 승인 기준→작은 구현→자동 회귀 검증→사용자의 실사용 판단→기록·릴리스

사용자가 계속 갖는 역할

  • 어떤 영상 작업을 얼마나 편하게 만들지 결정
  • 싱크·탐색·화질·입력 반응의 허용 기준 설정
  • 실사용 결과로 기능과 릴리스 판단
  • 범위·가격·지원 정책과 투자 우선순위 결정

하네스에 남길 역할

  • 변경 의도와 설계 이유를 짧게 기록
  • 같은 회귀 파일과 조건으로 비교
  • 파일 보호·취소·종료·설정 보존 검증
  • 실제 배포 DLL·설치본·플랫폼별 검증

머릿속의 큰 그림은 방향을 유지하는 자산이다. 세션을 넘기는 문서에는 결정한 이유, 지켜야 할 동작, 확인할 파일과 측정 조건을 남긴다. 같은 브랜드의 제품들은 시간 단위·회전·색 정보·원본과 결과의 관계를 설명하는 방식을 맞출 수 있다.

플랫폼과 제품이 늘면 검증 조합도 늘어난다. Player와 Trans의 엔진을 무리하게 합치기보다, 공통 테스트 영상·품질 기준·오류 분류·릴리스 기록부터 함께 관리하는 방법이 현실적이다. 한 제품의 변경이 다른 제품에 미치는 범위를 작게 유지한다.

지원 시간도 사업 비용이다. AI가 고객 답변과 수정안을 만들 수 있어도 재현 파일 확보, 문제 분류, 결과 확인과 릴리스 판단은 남는다. 매출과 함께 월 지원 시간·심각한 회귀·새 기능에 쓰는 시간을 기록한다.

09 / Execution

확장은 검증 결과를 따라 진행한다.

아래 순서는 개발 기간을 보장하는 일정이 아니라 단계별 의사결정안이다. 첫 4~8주에는 Player 출시 품질과 사용자 검증을 중심에 두고, Mac 이식 위험과 Trans의 출시 준비를 병행 검토한다.

1

출시 품질과 통합 브랜드의 기본 화면

PNG·배너 공유 문제와 통합 하네스를 고친다. 최신 설치본을 확인하고 Banana 사이트에 두 제품의 역할과 현재 지원 플랫폼을 표시한다. Trans의 GPL·스토어·실기기·결제 준비는 별도로 점검한다.

다음 단계 기준 · Player 기본 작업이 실제 배포본에서 통과하고, 알려진 제약과 지원 범위가 정리됨.
2

작은 사용자군의 재사용 확인

영상 반복 확인이 많은 사용자 20~30명에게 2~4주 사용하게 한다. 두 번째 주에도 사용했는지, 어느 작업에서 기존 플레이어 대신 열었는지, 어떤 파일에서 실패했는지 확인한다.

다음 단계 기준 · 반복 사용 이유가 여러 사용자에게 공통으로 나타남. 숫자는 제안하는 실험 규모이며 업계 기준이 아님.
3

첫 실제 결제와 제품 간 연결

지인이 아닌 사용자의 후원/유료 결제 3~5건과 이유를 확보한다. Player에서 Trans로 파일을 넘기거나 변환 결과를 여는 작은 연결을 시험하고, 실제로 두 제품을 함께 쓰는지 확인한다.

다음 단계 기준 · 후원과 기능 구매의 동기를 구분하고, 월 신규 구매자·교차 사용·지원 시간을 기록함.
4

Mac 베타와 반복 가능한 유입

작은 macOS 범위로 실제 사용자 테스트를 진행한다. 데모·검색·관련 커뮤니티 소개 중 반복 유입이 생기는 경로를 찾고, 플랫폼별 장애와 사용성을 비교한다.

다음 단계 기준 · 플랫폼이 늘어도 품질과 지원 시간을 감당하며 신규 사용자가 꾸준히 들어옴.
5

작업군 확대와 제품군 수익화

반복 요청이 많은 결과 비교·검토 기록·일괄 작업을 우선한다. 결제 이유와 사용자 겹침이 확인되면 유료 기능이나 번들을 실험한다. 독립 도구와 B2B QC는 별도 수요를 검증한 뒤 선택한다.

장기 목표 기준 · 여러 도구가 같은 작업을 완성하며 Banana가 특정 사용자군의 기본 선택으로 자리 잡음.

지금 집중할 세 가지

  1. 실제 배포본의 기본 동작: 캡처·파일 보호·종료·설정 보존부터 닫는다.
  2. 같은 브랜드의 제품 소개: “Player는 확인, Trans는 변환”을 실제 데모로 보여 준다.
  3. 재사용과 결제 이유: 다운로드 수보다 다음 주에도 쓰는 사람과 실제 구매 동기를 확보한다.
10 / Decision criteria

확신은 작업에서, 확장은 데이터에서.

확인할 신호왜 중요한가결과에 따른 판단
두 번째 주의 재사용호기심 다운로드와 생활 속 도구 사용을 구분재사용이 약하면 설명보다 기본 사용감과 타깃 작업을 수정

두 제품의 교차 사용통합 브랜딩이 실제 작업 편의로 이어지는지 확인겹침이 작으면 제품군을 유지하면서 타깃과 연동 방식을 조정

이 프로젝트는 출시 실험을 하겠다.

이미 구현된 제품과 동영상 도메인 경험이 있고, 같은 브랜드의 변환 도구까지 개발하고 있다. 작은 추가 투자로 첫 사용자와 결제를 확인할 수 있다는 점이 출시를 지지한다.

장기 비전은 유지한다. 첫 재사용 사용자, 첫 결제, 두 제품의 실제 연결, Mac에서의 반복 사용을 차례로 쌓아 선택한 동영상 작업군에서 영향력을 넓힌다. 전체 리그를 확보할 가능성은 아직 판단할 데이터가 없다.
